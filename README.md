# SplitSeat

A household subscription tracker with monthly totals and equal member shares. Add a full bill in USD, choose monthly or yearly billing, and enter comma-separated member names. Names combine case-insensitively across subscriptions. Annual charges divide by 12, and amounts round only for display, so displayed member shares may add up a cent differently.

The light interface works on phones and desktops, supports keyboard navigation, and announces changes and errors. Subscription and member names render as text. No account, external service, runtime dependency, or build step is needed.

Serve the repository with `python3 -m http.server 8080`, then open `http://localhost:8080`. Native browser modules require HTTP hosting. Assets and module imports use relative paths, including when hosted at `/splitseat-membrane/` on GitHub Pages. Publish the repository root after owner approval.

Data stays in this browser and does not sync across devices. The app saves a versioned record under `splitseat:v1` in localStorage. Examples appear only when no saved record exists. Deleting every subscription saves an empty household, which stays empty after reload. Invalid saved records are left untouched and disable persistence for that page session. Storage write failures show a warning; edits remain usable in memory but can be lost on reload. The app does not automatically reset or repair saved data.

Tabs in the same browser update when another tab changes saved subscriptions. Before adding or deleting, the app validates the latest saved list and applies only that edit, retaining any earlier session-only edits. A write failure keeps those edits locally; updates from other tabs do not discard them. A later successful edit attempts to save the pending edits together with the latest saved list. If saved data becomes corrupt or unreadable, saving is blocked for the remainder of that page session without overwriting it.

Where the browser supports Web Locks, edits and first-visit initialization are serialized across cooperating SplitSeat tabs. Without Web Locks, the app still refreshes before each edit and handles storage events, but localStorage cannot guarantee atomic read-modify-write across simultaneous tabs. Precisely concurrent edits can still race in that fallback. This is same-browser coordination, not cross-device syncing.

Run the service checks with `bun test tests/budget.test.js tests/storage.test.js`. Browser verification should cover add/delete, monthly/yearly billing, member merging, invalid input, reload, two-tab add/delete updates, pending session edits after write failures, deleting the final entry, corrupt saved data and unavailable storage. Check keyboard focus and the layout at narrow and wide widths. These service checks alone do not verify the browser interface.

Development uses Membrane. The owner reviews task access, delivers pinned capsules, reviews reported decisions, prepares a checked candidate, and accepts it separately. Source checkout commits are not accepted Membrane revisions. The owner exports accepted code before publishing. The launch app is live at [SplitSeat](https://meshankhosla.github.io/splitseat-membrane/), with source in the [GitHub repository](https://github.com/MeshanKhosla/splitseat-membrane). The tab-coordination fix has been accepted and published. The new release-versioned asset URLs require separate owner acceptance and publication.

Release asset URLs use the token `cross-tab-v1` in `index.html`, for both the stylesheet and entry script. Bump their `?v=` tokens when those assets change so returning browsers request the new release. Query strings on the entry script do not propagate to its imported modules. When a dependency module changes, invalidate its own import URL in every importing module, then invalidate those importers up to the HTML entry point. Apply this throughout the changed dependency chain; an entry-script version alone does not refresh unchanged import URLs. Verify the deployed HTML references the intended token and returning tabs execute the current release before repeating browser regression checks.
